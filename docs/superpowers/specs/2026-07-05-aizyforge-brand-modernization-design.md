# AIzyForge「智企云枢」品牌改造设计

## 目标

将当前系统统一品牌化为：

- 中文产品名：`智企云枢`
- 英文技术品牌：`AIzyForge`
- GitHub 仓库名：`aizyforge-core`
- 生产域名：`https://aixy99.site`
- 备案号：`冀ICP备2026021324号`

完成后，公众页面、登录后的管理端、浏览器元数据、接口文档、运行时数据库数据和部署标识均不再展示原项目的品牌、推广链接、演示账号或演示资源。内部 Java 包、Maven 模块和数据库技术标识保持兼容，不做高风险的全量重命名。

## 品牌使用规则

### 对外显示

- 页面标题、登录页、菜单标题、页脚、验证码水印统一显示 `智企云枢`。
- 需要中英文同时出现的场景使用 `AIzyForge 智企云枢`。
- 宣传描述统一为：`面向企业的一体化智能管理平台`。
- 页脚保持现有备案号，不增加原项目或第三方推广信息。

### 技术标识

新建或可安全修改的技术标识统一使用小写 `aizyforge`：

- GitHub 仓库：`aizyforge-core`
- 前端包名：`aizyforge-ui-admin`
- Spring 应用名：`aizyforge-server`
- systemd 服务：`aizyforge.service`
- 服务器目录：`/opt/aizyforge`、`/var/www/aizyforge`
- 服务器配置目录：`/etc/aizyforge`

以下兼容性标识继续保留：

- Java 包：`cn.iocoder.yudao`
- Maven 模块和 artifactId：`yudao-*`
- 前端源码目录：`yudao-ui/yudao-ui-admin-vue3`
- 数据库中业务表名、Redis 键前缀以及现有序列化类名
- Git 的 `upstream` 官方远端
- MIT `LICENSE` 及其版权和许可文本

## Logo 与视觉资源

Logo 使用“云端枢纽节点”抽象图形，表达云平台、连接和企业协同：

- 主色使用蓝紫渐变，兼容浅色和深色背景。
- 图形不包含旧项目兔子、人物照片或第三方商标。
- 横向组合显示图形与 `智企云枢`，小尺寸仅显示图形。
- 同一图形派生 favicon、登录页 Logo、加载动画静态帧和默认头像。
- 不引入远程图片，所有基础品牌资源随前端构建产物发布。

首期只制作一套稳定、清晰的品牌资源，不扩展完整营销视觉系统。

## 前端改造

### 标题与登录

- `VITE_APP_TITLE` 修改为 `智企云枢`，让登录页、侧边栏和页脚自动继承。
- HTML title、description、keywords 改为智企云枢相关内容。
- 默认租户名与数据库主租户保持一致，设置为 `智企云枢`。
- 取消前端预填默认用户名和密码。
- 移除登录页中的官方教程、视频、面试手册和外包咨询入口。
- 社交登录、手机登录等辅助入口不再写死旧租户名。

### 首页与导航

- 首页删除原项目仓库卡片、Star 引导、作者动态和推广公告。
- 首页保留企业管理平台所需的模块入口、待办、公告和统计占位，不伪造项目数和访问量。
- 用户菜单中的“文档”入口在没有自有帮助中心前直接移除。
- 生产环境关闭 `DocAlert`，避免 231 个业务页面跳转原项目文档。
- 数据库中的作者动态、Boot 文档、Cloud 文档菜单设为不可用。

### 外部资源

- 清除前端运行时对 `*.iocoder.cn`、原项目 GitHub/Gitee 仓库及演示图片的依赖。
- 商城 H5、GoView、地图等未配置的外部系统不再默认指向演示地址。
- 示例数据所需图片改为本地静态资源或空占位。
- 清除原百度统计标识；未提供自有统计标识时不加载统计脚本。
- 百度地图 Key 置空并通过部署环境按需注入。

## 后端改造

- Spring 应用名修改为 `aizyforge-server`。
- Swagger 标题修改为 `智企云枢开放接口`，描述修改为企业综合管理平台接口说明。
- Swagger URL 指向 `https://aixy99.site`，仓库和许可证链接指向新仓库及本地许可证。
- 验证码水印修改为 `智企云枢`。
- Spring Boot 启动横幅修改为 `AIzyForge 智企云枢`。
- POM 的项目描述和仓库 URL 更新为 AIzyForge；内部 artifactId 不改。
- 接口示例中的旧品牌名称替换为中性示例值，例如“示例用户”“示例企业”，不改变字段含义。

## 数据库改造

数据库变更使用可重复执行的迁移脚本，并同步更新 MySQL 初始化 SQL。

### 保留并更新

- 保留管理员账号 `admin` 及其当前随机密码。
- 主租户名称改为 `智企云枢`，网站域名改为 `aixy99.site`。
- 管理员昵称改为 `系统管理员`，移除原头像、邮箱和手机号。
- 默认部门、OAuth 默认客户端和必要的系统配置改为智企云枢名称。

### 清理演示数据

- 逻辑删除或禁用非必要演示租户和演示账号。
- 撤销演示账号的访问令牌和会话。
- 删除作者动态、官方文档菜单、原项目公告和推广内容。
- 删除或禁用演示 OAuth 客户端，仅保留系统实际使用的默认客户端。
- 删除指向官方演示站点的头像、公告图片和对象存储地址。
- 清除初始化 SQL 中的演示云存储访问密钥，禁用未配置的存储客户端。

执行生产迁移前必须备份数据库；迁移后检查管理员登录、租户解析、菜单加载和文件上传配置。

## 密钥与安全配置

- 所有看似有效的 AI、快递、对象存储、数据库和第三方 API 密钥均视为已泄露，不继续沿用。
- 代码中的密钥改为环境变量引用；未配置时对应集成功能默认关闭。
- 生产机密仅放在 `/etc/aizyforge/aizyforge.env`，权限为 `root:aizyforge 0640`。
- 前后端 API 加密键成对轮换；明确它们是客户端可见的传输混淆键，不能替代 HTTPS。
- 初始化 SQL 不再包含可用访问密钥、默认弱密码或真实联系人信息。
- 通过密钥扫描确认 Git 工作区和构建产物中不存在新增明文凭据。

已有凭据需要在对应第三方平台执行吊销或轮换；仅从源码删除不能消除泄露风险。

## 仓库与部署改造

### GitHub

- 将仓库 `AIzy920555014/aizforge-core` 重命名为 `AIzy920555014/aizyforge-core`。
- 本地 `origin` 更新到新 SSH 地址。
- `upstream` 保持指向原开源项目，继续用于获取官方更新。
- README 改写为智企云枢项目说明，同时保留 MIT LICENSE。

### 服务器

- 新建 `/opt/aizyforge`、`/var/www/aizyforge` 和 `/etc/aizyforge`。
- 创建并启用 `aizyforge.service`，新服务验证通过后再停用旧 `aizforge.service`。
- Nginx 站点配置和静态资源根目录切换到 `aizyforge` 路径。
- 域名、HTTPS 证书和备案号保持不变。
- 旧发布目录和服务文件保留到验收完成，作为快速回滚入口。

## 验证策略

### 静态验证

- 用户可见源码、生产配置、HTML 元数据和初始化数据中不存在旧品牌文本或官方推广地址。
- 允许旧技术名出现的范围仅限兼容性清单、测试夹具、历史设计文档、LICENSE 和 upstream 配置。
- 前端源代码与构建产物不包含官方统计标识、默认登录密码或远程演示图片。
- 密钥扫描不发现新增明文凭据。

### 构建验证

- 前端依赖安装、类型检查和生产构建通过。
- 后端编译、测试和可执行 JAR 打包通过。
- 数据库迁移脚本在备份副本上可重复执行。

### 浏览器验证

- 桌面与移动端登录页仅显示智企云枢品牌、Logo 和备案号。
- 登录后首页、导航、页脚、用户菜单和 AI 空状态不显示旧品牌。
- 浏览器 title、favicon、SEO 元数据和控制台输出使用新品牌。
- 页面没有指向原项目官网、文档、仓库或演示图片的可点击入口。
- 控制台无混合内容、资源加载失败或与品牌改造相关的错误。

### 线上验证

- `https://aixy99.site` 首页、登录、后台首页、Swagger 和健康检查正常。
- 管理员可使用当前随机密码登录。
- `aizyforge.service`、Nginx、MariaDB、Redis 和证书续期服务正常。
- GitHub 仓库名称与本地 `origin` 均为 `aizyforge-core`。

## 回滚

- 修改生产数据库前创建带时间戳的完整备份。
- 前后端保留上一版本发布包和软链接目标。
- 新 systemd 服务未通过健康检查前不删除旧服务。
- Nginx 配置先执行语法检查，再 reload。
- 若登录、菜单或文件配置异常，回滚数据库、服务文件和前端 `current` 软链接。

## 验收标准

- 对外统一显示 `智企云枢`，技术品牌统一为 `AIzyForge`。
- GitHub 仓库和安全技术标识统一使用 `aizyforge`。
- 活跃页面、接口文档和数据库展示数据不再出现旧品牌与官方推广资源。
- 内部包名和模块名保持兼容，现有业务功能没有因品牌改造受损。
- 演示账号、统计代码、远程演示资源和明文密钥得到清理。
- 本地构建、数据库迁移、管理员登录和线上运行均通过验证。
